# Legacy external-input routine inventory

Evidence level: `SOURCE_BOUND_B0_AUDIT` plus public TTUTIL capability context where explicitly noted.

The revision-53 parser is concentrated in `input1.for` but the external boundary is not owned by one routine. Dynamic management, crop, soil-temperature and hydrology reads occur elsewhere. `Output_Init` is included because its formatted state output can be used as future initial state and therefore defines a serialization seam.

## Parser helpers that materially define the contract

`Findadr` rewinds and scans exact eight-character records. Section order is therefore generally free for sections located with `Findadr`, but duplicate section labels resolve to the first occurrence. Missing labels set an error. `Findadrfix` does not rewind and is used for sequential management event discovery, so event order is material.

`ReadOp`, `Readvals`, `Readints` and `ReadTs` read the next record. Despite the `name=value` appearance of ANIMO41 GENERAL, these helpers are sequence-sensitive. `Readvals`, `Readints` and `ReadOp` use `=` and `!` positions to delimit values. This is incompatible with treating the historical file as an ordinary order-independent TTUTIL file.

The direct-file parser is different again: the first seven characters select `Animo40` or `Animo41`; subsequent records are split into a four-character selector and an 80-character file string. `Strip` expects a closing double quote. This routing grammar requires its own test contract.
