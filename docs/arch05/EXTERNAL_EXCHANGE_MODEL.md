# ANIMO-ARCH05 external exchange model

Status: `CANDIDATE_ARCHITECTURE_DESIGN`.

## Boundary principle

ANIMO5 consumes explicit exchange values. It does not dereference another model's internal state and external models do not dereference ANIMO internal state.

The contract distinguishes four things that legacy integrations often mix together:

1. ownership of persistent physical state;
2. observation of that state by another model;
3. interval forcing or transfer data;
4. transaction control deciding whether a proposed coupled interval is accepted.

These concepts must remain separate in the API and in checkpoint logic.

## Frame model

A coupled ANIMO trial receives immutable frames bound to one exact trial identity and interval. A frame is not a pointer to mutable producer memory.

Each producer frame carries compatibility identity sufficient to reject stale or incompatible data before process execution. At minimum this includes schema identity, producer identity/version, accepted generation, interval bounds, geometry, feature layout, physical layout and precision-policy reference.

The same field values may be reused for a retry only through a new trial binding. A previously identified frame cannot be silently mutated and reused under the same identity.

## Hydrology ownership

Hydrological water state remains externally owned. ANIMO receives accepted/start and proposed/end water coordinates plus interval-integrated water transfers required by transport and conservation views.

This allows the ANIMO kernel to evaluate solute transport and ledger projection without storing a duplicate hidden hydrology state.

The exchange field set is semantic. Legacy names such as `FLAB`, `FLD`, `RU` or `Sic` are evidence for required physical information but are not future API names.

Chemical composition of irrigation, runon, deposition or upward boundary water is not embedded implicitly in the hydrology owner. Those concentrations or material compositions belong to explicit chemistry forcing or typed material-event contracts.

## Crop ownership

When `crop_mode=external`, persistent crop state belongs to the crop owner. ANIMO receives only the crop observations and uptake demands required by the selected process/ledger contract.

ANIMO returns realized nutrient uptake as trial results linked to the typed transfer journal. It does not mutate externally owned crop N or P state.

If crop residues, exudates, harvest returns or similar transfers are generated by the external crop model, they cross the boundary as explicit typed quantity bundles. Soil additions must not be inferred from unexplained differences between two crop state snapshots.

For combined soil+crop conservation views, the external crop owner may also expose accepted/trial crop N, P and dry-matter observations plus explicit harvest/grazing export bundles. These observations remain externally owned state.

## Transaction ownership

The coupling orchestrator owns the logical coupled trial lifecycle. ARCH05 does not define the future timestep controller, but it requires that all models participating in one coupled interval can be rejected without partial physical commit.

Conceptually:

1. bind accepted-state generations and immutable exchange frames;
2. evaluate producer trial if needed;
3. evaluate ANIMO trial against those frames;
4. exchange trial results such as realized uptake;
5. orchestration decides accept or reject under a later qualified TIME policy;
6. accept promotes all participating generations as one logical interval;
7. reject leaves all accepted physical states unchanged.

ANIMO is therefore not allowed to commit physical state merely because its local process evaluation completed successfully.

## Result versus state

A realized transfer result is not itself persistent state. For example `CROP-N-UPTAKE-REALIZED` describes the N transfer generated by an ANIMO trial. On coupled accept the same physical event may be consumed by the crop owner to update its state and by the MassLedger observer to project whole-system closure. The event is represented once rather than booked independently by each model.

## Fail-closed compatibility

A frame is rejected before physical execution when relevant identity does not match. Examples include:

- different layer geometry despite equal layer count;
- wrong hydrology mode;
- wrong external exchange field/unit schema;
- stale accepted producer snapshot;
- external crop frame supplied while `crop_mode` is not external;
- macropore fields supplied without matching admission identity;
- producer frame interval that does not match the bound ANIMO trial;
- state/feature/precision representation mismatch covered by `physical_layout_id`.

No implicit resizing, unit guessing, field defaulting, or silent stale-frame reuse is allowed.

## Checkpoint implication

ANIMO checkpoints retain only ANIMO-owned accepted state plus exchange/configuration identity references required for compatibility. External hydrology and external crop state remain in their owners' checkpoints.

A coordinated restart therefore requires the orchestrator to restore mutually compatible accepted generations, not to reconstruct foreign state from an ANIMO checkpoint.

## Qualification boundary

ARCH05 defines a candidate information and ownership boundary. It does not prove that a SWAP or WOFOST implementation already supplies these fields, does not define their concrete language ABI, and does not admit an exchange gate. Behavioural coupling, TIME semantics, rollback implementation, synchronization policy and reference comparison remain future qualification work.
