# ANIMO-STATEQ11 Qualification Rationale

The bounded TCD-042 application now has several continuation responsibilities that are individually explicit but not yet bound to one accepted transaction identity.

KT02 owns accepted science lineage, generation and time. STATEQ09 owns accepted endpoint to next detailed-hydrology origin transfer. STATEQ08 establishes that `Runinu` is separate detailed-mode execution continuation. BOUNDQ02 owns static-boundary year cursor semantics.

If those values are persisted or advanced independently, a later interval can combine science state from one generation with hydrology or boundary forcing state from another.

STATEQ11 prevents that ambiguity by defining one composite continuation candidate with the same lineage, generation and exact accepted time as KT02.

The candidate does not commit anything. It defines what must move together and provides exact coherence validation against the accepted store.

The first interval remains fail-closed around `Runinu`: STATEQ10 can source-normalize `Pn/Sic/Snla/Mofro`, but no source authority defines a first-call `Runinu`. STATEQ11 therefore requires that value explicitly and records no historical claim.

Positive qualification means:

`THE_BOUNDED_APPLICATION_CONTINUATION_COMPONENTS_CAN_BE_TYPED_AND_IDENTITY_BOUND_TO_ONE_KT02_ACCEPTED_GENERATION`.

It does not mean the composite is yet canonical state or that an atomic multi-owner commit has been implemented.
